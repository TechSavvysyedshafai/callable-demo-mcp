How to write a requirement 
Feature: Motor insurance quote
Default: Quote issued at standard premium

Field: Driver age | number | 18..75 | required
Field: Vehicle value | number | 1000..150000 | step 500
Field: Cover type | choice | Comprehensive, Third party only
Field: Pre-authorisation obtained | yesno | required
Field: Registration number | text | max 8 | required

Rule R1: Driver age < 25 AND Cover type = Comprehensive => Apply 20% loading
  • Field types: number (add step 0.01 for decimals), choice, yesno, text.
  • Field limits: 18..75, min 0, max 8 (characters, for text), required.
  • Rule conditions: >, >=, <, <=, =, != joined with AND. For OR, write two rules with the same outcome.
  • Default: what happens when no rule applies.

Generated UAT pack

The techniques, in plain words
Happy path
One normal, valid case that should go straight through.
Boundary value
Values at each limit and one step either side, where most input bugs hide.
Equivalence class
One test for each kind of valid choice, and one invalid one.
Required field
The field left blank must be stopped with a clear message.
Invalid format
Letters typed into a number field must be stopped.
Decision rule
Each rule is tested where it just applies, then each condition is switched off on its own to prove it matters.

Expected results come from the rules as written, so a wrong rule gives a wrong expectation. Review the requirement questions first. Dates and rules that compare two fields are not supported yet.
